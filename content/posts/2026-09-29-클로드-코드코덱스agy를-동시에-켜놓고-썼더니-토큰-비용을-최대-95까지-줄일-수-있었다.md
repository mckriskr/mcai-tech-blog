결론부터 말하면: 클로드 코드(Claude Code), 코덱스(Codex CLI), agy(Antigravity CLI, 구글의 코딩 에이전트) 세 개를 M1 Max 32GB 맥북 한 대에서 같이 쓸 때 가장 확실하게 토큰(token — AI가 글을 읽고 쓰는 최소 단위, 대략 영어 단어 하나 정도라고 생각하면 된다) 비용을 줄이는 방법은 "프롬프트 캐싱"과 "모델 등급 나눠쓰기" 딱 두 가지였다. 나머지 방법들(저장소 지도, MCP 도구 등)도 도움이 되긴 하는데, 실제로 얼마나 절감되는지 공식 수치가 없어서 "확실히 좋다"고 단정할 수는 없었다. 오늘은 그 조사 과정을 그대로 풀어본다.

## 왜 코딩 에이전트를 세 개나 동시에 켜놓게 됐나

McAI는 로컬 모델로 코딩을 시키는 프로젝트지만, 실제로 작업하다 보면 클로드 코드·코덱스·agy처럼 큰 회사의 코딩 에이전트도 같이 켜놓고 비교하거나 보조로 쓰는 경우가 생긴다. 문제는 이 셋을 M1 Max 32GB라는 한 대의 노트북에서 동시에 돌리면, 돈(토큰 비용)도 많이 나가고 메모리도 부족해진다는 것이다. 그래서 "정확히 어떤 방법이 얼마나 아껴주는지" 숫자로 확인해보기로 했다.

## 프롬프트 캐싱 하나로 90~95% 할인받은 방법

프롬프트 캐싱(prompt caching — 매번 같은 내용을 처음부터 다시 보내는 대신, 한 번 보낸 내용을 잠깐 저장해뒀다가 재사용해서 싸게 처리하는 방식)은 세 회사 API 전부가 제공하는 기능이다. Anthropic(클로드), OpenAI(코덱스), Google(agy/Gemini)이 공식 문서에서 밝힌 숫자를 그대로 옮기면:

- **Anthropic**: 캐시에서 읽은 토큰은 정가의 10%(즉 90% 할인). 캐시에 처음 저장할 때는 오히려 정가의 1.25배가 든다.
- **OpenAI**: 마찬가지로 캐시된 입력 토큰은 90% 할인. 예를 들어 GPT-6 Sol은 입력가 $4/백만 토큰인데 캐시되면 $0.40/백만 토큰이 된다. 캐시 유지 시간은 5~10분이다.
- **Google Gemini**: 2.5 이상 모델은 90% 할인, 2.0 모델은 75% 할인. 자동으로 켜지는 "암묵적 캐싱"은 공짜지만, 직접 설정하는 "명시적 캐싱"은 저장해두는 동안 시간당 별도 요금(100만 토큰당 시간당 $0.50)이 붙는다.

셋 다 설정을 따로 만질 필요 없이 거의 기본으로 작동한다는 공통점이 있다 — 그래서 난이도가 제일 낮은데 효과는 제일 큰 방법이다.

## 모델을 나눠 쓰면 정확히 얼마나 싸지나 — 직접 계산해봤다

간단한 작업은 저렴한 모델에게, 복잡한 작업만 비싼 모델에게 맡기는 "모델 등급 나눠쓰기"도 확인해봤다. Anthropic의 2026-09-29 기준 공식 가격표(백만 토큰당)는 이렇다.

| 모델 | 입력 가격 | 출력 가격 | 캐시 읽기 가격 | 캐시 읽기 할인율 |
|---|---|---|---|---|
| Claude Opus 5.5 | $4.00 | $20.00 | $0.20 | **95%** |
| Claude Sonnet 5.5 | $2.00 | $10.00 | $0.20 | 90% |
| Claude Haiku 4.5 | $1.00 | $5.00 | $0.10 | 90% |

직접 계산해보다가 재미있는 걸 하나 발견했다. Haiku는 Opus보다 입력가가 1/4밖에 안 되는데(가장 저렴한 모델), **캐시를 쓸 때 실제로 가장 크게 할인받는 건 오히려 제일 비싼 Opus다.** 이유는 Opus의 캐시 읽기 가격이 Sonnet과 똑같이 $0.20으로 고정돼 있어서, 원래 가격($4)의 5%밖에 안 되기 때문이다(=95% 할인). Sonnet·Haiku는 캐시를 써도 90% 할인에 그친다. 즉 "비싼 모델일수록 캐싱을 켰을 때 상대적으로 더 이득"이라는, 공식 문서에 대놓고 안 적혀 있는 사실을 직접 가격표를 계산해보고서야 알게 됐다.

## 그럼 저장소 지도나 MCP 도구는 안 써도 되나

Aider라는 도구는 저장소 안의 함수·클래스 구조를 나무 모양으로 분석(tree-sitter라는 기술 사용)해서, 어떤 파일이 서로 얼마나 연결돼 있는지를 PageRank(페이지랭크 — 구글 검색이 웹페이지 중요도를 매기던 그 방식을 코드 파일에 적용한 것)로 점수 매긴 뒤, 중요한 부분만 압축해서 AI에게 보여주는 "저장소 지도" 기능을 갖고 있다. Serena 같은 MCP(Model Context Protocol — AI 에이전트가 외부 도구를 표준화된 방식으로 불러 쓰게 해주는 규격) 도구는 파일 전체를 읽는 대신 정확한 함수 정의 위치만 콕 집어 가져온다.

둘 다 원리상 토큰을 아껴줄 것 같고, 실제로 McAI도 `graft`라는 비슷한 원리의 코드 그래프 도구를 코딩 작업에 쓰고 있다(호출할 때마다 "이번에 토큰 몇 개 절감했다"는 걸 바로 알려주는 방식이다). 하지만 정직하게 말하면, Aider나 Serena 어느 쪽도 "이 기능으로 토큰을 정확히 몇 % 줄였다"는 공식 비교 수치를 공개한 적이 없다 — 효과가 있다는 정황은 충분하지만, 정확한 숫자는 확인되지 않았다.

## 토큰을 줄이는 것과 돈을 줄이는 것은 다른 이야기다

조사 중에 "Token Reduction Is Not Cost Reduction"(토큰 절감이 곧 비용 절감은 아니다)이라는 논문을 발견했다. 핵심 주장은, 내용을 요약하거나 압축해서 토큰 수를 줄이는 그 작업 자체에도 별도의 계산 비용이 든다는 것이다. 그래서 "토큰 몇 개 줄었다"만 보지 말고, 그 줄이는 과정까지 포함한 전체 비용을 봐야 한다.

## M1 Max 32GB에서 세 개를 동시에 켜면 실제로 벌어지는 일

여기서부터는 토큰 비용과는 완전히 다른 문제다. 클로드 코드는 서브에이전트(sub-agent — 원래 대화와 별도로 자기만의 작업 공간을 갖고 일하다가 결과만 요약해서 돌려주는 보조 일꾼)를 쓸 때마다 저장소를 통째로 복제한 워크트리(worktree — 같은 저장소를 여러 개 복사해서 동시에 작업할 수 있게 해주는 git 기능)를 새로 만든다. 서브에이전트를 5개 띄우면 저장소가 5벌 디스크에 동시에 생긴다는 뜻이다 — 이건 돈이 아니라 저장 공간과 메모리를 잡아먹는 문제다.

실제로 클로드 코드의 공식 최소 사양은 4GB지만, 커뮤니티에서는 본격적으로 여러 에이전트를 동시에 쓰려면 16GB 이상을 권장한다는 이야기가 많다. 극단적인 사례로는 클로드 코드가 129GB까지 메모리를 잡아먹었다는 실사용자 버그 보고도 있었다(일반적인 상황은 아니고, 버그로 보고된 사례다). M1 Max 32GB에서 세 개(클로드 코드+코덱스+agy)를 동시에 켰을 때 정확히 메모리를 얼마나 쓰는지 공식적으로 측정한 자료는 이번 조사에서 찾지 못했다 — 이 부분은 솔직히 확인 안 된 채로 남겨둔다.

## 정리: 방법별 절감 효과 한눈에 보기

| 기법 | 공식 절감 수치 | 적용 난이도 | 세 도구와의 관련성 |
|---|---|---|---|
| 프롬프트 캐싱(클로드/코덱스) | 캐시 히트 시 90% 할인 | 낮음(대부분 기본 적용) | 클로드 코드·코덱스 직접 관련 |
| 컨텍스트 캐싱(Gemini/agy) | 90%(2.5+) / 75%(2.0) 할인 | 낮음~중간 | agy(Antigravity) 직접 관련 |
| 모델 등급 나눠쓰기 | 입력가 최대 1/4, 캐시 시 최대 95% 할인(Opus) | 낮음(라우팅 규칙만 필요) | 세 도구 모두 관련 |
| 저장소 지도(Aider류) | 확인 안 됨(방식만 검증됨) | 중간 | 간접 관련 |
| 서브에이전트 컨텍스트 격리 | 확인 안 됨(목적만 검증됨) | 낮음(클로드 코드 내장) | 클로드 코드 직접 관련 |
| MCP 코드그래프(Serena류) | 확인 안 됨(정성적 주장만) | 중간(별도 설치 필요) | 세 도구 모두 관련 |

## 결론: 우리가 고른 조합

숫자로 확실히 증명된 두 가지, **프롬프트/컨텍스트 캐싱**과 **모델 등급 나눠쓰기**를 우선 켜두는 것이 가장 확실한 방법이라는 결론을 내렸다. 특히 비싼 모델(Opus)을 반드시 써야 하는 작업일수록 캐싱을 켜두면 상대적으로 더 크게(95%까지) 아낄 수 있다는 게 이번 조사에서 새로 확인한 사실이다. 저장소 지도나 MCP 도구는 효과가 없다는 뜻이 아니라, 아직 "정확히 얼마나 좋은지"를 숫자로 증명할 공식 자료가 없다는 뜻이니, 이 부분은 McAI가 이미 쓰고 있는 `graft` 같은 도구의 실제 사용 기록을 직접 모아 비교해보는 게 다음 숙제로 남았다.
